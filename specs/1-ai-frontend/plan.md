# Frontend Technical Plan: AI-Themed Todo Application

## 1. Technical Context

### Feature Overview
- **Feature**: AI-Themed Todo Web Application Frontend
- **Requirements**: Build a visually stunning, modern AI-themed frontend for a multi-user Todo application using Next.js 16+ (App Router), TypeScript, Tailwind CSS, and Better Auth (with JWT plugin)
- **Primary Goal**: Create a next-generation AI-native dashboard experience with futuristic UI elements, glassmorphism, and cyber-tech aesthetics

### Implementation Approach
- **Framework**: Next.js 16+ with App Router
- **Language**: TypeScript with strict mode
- **Styling**: Tailwind CSS with custom extensions for AI theme
- **Authentication**: Better Auth with JWT plugin
- **API Client**: Custom typed fetch wrapper
- **Component Strategy**: Server Components by default, Client Components for interactivity

### Known Constraints
- Use Tailwind CSS utility classes only, no custom CSS
- No external UI libraries (shadcn, radix, etc.)
- Must enforce user isolation for tasks
- Implement proper loading/success/error states
- Focus on performance and accessibility

## Phase 0: Research & Unknown Resolution

### Research Summary

#### Decision: Framework and Tech Stack
- **Rationale**: Next.js 16+ with App Router provides the modern foundation required for this AI-themed application. TypeScript with strict mode ensures code quality and maintainability. Tailwind CSS offers the flexibility needed for the unique AI aesthetic without restricting customization.
- **Alternatives considered**: React with CRA vs Next.js; Styled-components vs Tailwind; Simple Auth vs Better Auth
- **Choice justification**: Next.js App Router simplifies routing and provides excellent performance characteristics needed for a responsive UI. Better Auth with JWT plugin offers seamless integration with the backend security requirements.

#### Decision: Component Strategy
- **Rationale**: Server Components by default with Client Components only for interactivity optimizes performance. This approach minimizes client-side JavaScript while enabling interactive elements where needed.
- **Alternatives considered**: Client Components by default vs Server Components by default
- **Choice justification**: Server Components reduce bundle size and improve loading times, which is crucial for the smooth, responsive experience needed for the AI-themed UI.

#### Decision: Authentication Flow
- **Rationale**: Better Auth with JWT plugin provides seamless integration with the backend security infrastructure while offering a clean developer experience.
- **Alternatives considered**: NextAuth.js vs Better Auth; Cookie-based vs JWT-based auth
- **Choice justification**: Better Auth's JWT plugin aligns perfectly with the backend's JWT verification requirements and provides excellent integration with Next.js App Router.

## Phase 1: Design & Contracts

### Data Model: AI-Themed Todo Frontend

#### Entities

**Task Entity**
- **Fields**:
  - `id`: number (unique identifier)
  - `title`: string (required, task title)
  - `description`: string (optional, task description)
  - `completed`: boolean (task completion status)
  - `createdAt`: string (timestamp of creation)
  - `updatedAt`: string (timestamp of last update)
- **Validation**:
  - `title` must be non-empty string (min 1 character)
  - `completed` defaults to `false`
  - `createdAt` and `updatedAt` are ISO date strings
- **State Transitions**:
  - `pending` → `completed` when task is marked complete
  - `completed` → `pending` when task is marked incomplete

**TaskCreateInput Entity**
- **Fields**:
  - `title`: string (required, task title)
  - `description`: string (optional, task description)
- **Validation**:
  - `title` must be non-empty string
  - `description` is optional, max length TBD

**TaskUpdateInput Entity**
- **Fields**:
  - `title`: string (optional, new task title)
  - `description`: string (optional, new task description)
  - `completed`: boolean (optional, completion status)
- **Validation**:
  - At least one field must be provided
  - If `title` provided, must be non-empty string
  - `completed` if provided, must be boolean

### API Contracts

#### Authentication Endpoints
```
POST /api/auth/signup
- Request: { email: string, password: string, name?: string }
- Response: { success: boolean, token?: string, error?: string }

POST /api/auth/signin
- Request: { email: string, password: string }
- Response: { success: boolean, token?: string, error?: string }
```

#### Task Management Endpoints
```
GET /api/tasks
- Headers: Authorization: Bearer {token}
- Response: { tasks: Task[] }

POST /api/tasks
- Headers: Authorization: Bearer {token}
- Request: TaskCreateInput
- Response: { task: Task, error?: string }

GET /api/tasks/{id}
- Headers: Authorization: Bearer {token}
- Response: { task: Task, error?: string }

PUT /api/tasks/{id}
- Headers: Authorization: Bearer {token}
- Request: TaskUpdateInput
- Response: { task: Task, error?: string }

DELETE /api/tasks/{id}
- Headers: Authorization: Bearer {token}
- Response: { success: boolean, error?: string }

PATCH /api/tasks/{id}/complete
- Headers: Authorization: Bearer {token}
- Request: { completed: boolean }
- Response: { task: Task, error?: string }
```

### Quickstart Guide

#### Initial Setup
1. Clone the repository and navigate to the frontend directory
2. Install dependencies: `npm install`
3. Set up environment variables as specified in `.env.example`
4. Run development server: `npm run dev`

#### Running the Application
1. Ensure backend API server is running
2. From the frontend directory, run: `npm run dev`
3. Visit http://localhost:3000 in your browser

#### Key Development Commands
- `npm run dev` - Start development server
- `npm run build` - Build for production
- `npm run start` - Start production server
- `npm run lint` - Run linter
- `npm run type-check` - Run TypeScript checker

2. **Authentication Layer**

3. **UI Component Library**
   - Build core reusable components (GlassCard, TaskCard, etc.)

4. **Task Management Features**

5. **Polish & Optimization**

### Critical Components

**GlassCard Component**
- Purpose: Reusable container with glassmorphism effect
- Props: children, className, variant
- Features: Backdrop blur, semi-transparent background, customizable styling

**TaskCard Component**
- Purpose: Display individual task with AI-themed styling
- Props: task data, callbacks for actions
- Features: Animated checkbox, hover effects, completion indicator

**API Client**
- Purpose: Centralized, typed API access
- Methods: getTasks, createTask, updateTask, deleteTask, toggleComplete
- Features: Automatic JWT token attachment, error handling, loading states
