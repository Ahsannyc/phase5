# Constitution Update for Phase 3: AI Todo Chatbot

## Summary

Updated the project constitution to evolve from Phase 2 (Todo app) to Phase 3 (AI Todo Chatbot with MCP and OpenAI Agents SDK integration). The constitution now includes requirements for AI/Chatbot functionality, MCP server implementation, OpenAI Agents SDK usage, and stateless conversation persistence.

## Original Request

```
# Project Constitution – Phase 3: AI Todo Chatbot (Full Integration)
Evolution of Todo Hackathon – Spec-Driven Development

Last updated: [insert today's date – e.g. February 2026]

## 1. Core Philosophy & Binding Rules

1. **Strict Spec-Driven Development (SDD)**
   - Specifications are the single source of truth.
   - All code must be generated by Claude Code from approved Markdown specs.
   - Manual coding is forbidden except for very minor formatting fixes.
   - Every feature starts with spec → plan → tasks → implement → test.

2. **No manual coding outside Claude Code**
   - Use `sp specify`, `sp plan`, `sp implement` workflow.
   - All agents must reference constitution.md and relevant @specs/... files.

3. **Agent & Skill Boundaries (Strict)**
   - Spec Writer → specs only (never code)
   - Architecture Planner → plans & architecture.md only
   - Database Engineer → SQLModel models & migrations only
   - Backend Engineer → FastAPI endpoints & business logic only
   - Frontend Engineer → Next.js UI & ChatKit only
   - ChatKit Frontend Agent → ChatKit config & chat UI only
   - MCP Engineer → MCP server & tools only
   - AI Agent Engineer → OpenAI Agents SDK runner & prompt only
   - Integration Tester → end-to-end tests only (after others complete)

4. **Always require spec approval**
   - Every coding agent **must** ask:
     "Are the relevant specs (e.g. API + Database / UI + Chat / MCP + Agent) approved?"
     before generating any code.

5. **Multi-user & Security is mandatory**
   - Every task & conversation belongs to exactly one user (enforced by user_id)
   - JWT verification on every protected endpoint (401/403)
   - No cross-user data access allowed — ever

## 2. Technology & Stack Decisions (Phase 2 + Phase 3)

### Monorepo structure
todo-app/ ├── frontend/ # Next.js 16+ App Router, TypeScript, Tailwind, ChatKit ├── backend/ # FastAPI, SQLModel, Alembic, OpenAI Agents SDK ├── specs/ # features/api/database/ui/mcp/agent/chat ├── skills/ # reusable modules ├── subagents/prompts/ ├── tests/ ├── migrations/ ├── docker-compose.yml ├── .env └── constitution.md

text
### Frontend
- Next.js 16+ (App Router)
- TypeScript (strict)
- Tailwind CSS (utility classes only)
- Better Auth (JWT plugin)
- OpenAI ChatKit (conversational UI)
- Env: NEXT_PUBLIC_OPENAI_DOMAIN_KEY (domain allowlist)

### Backend
- FastAPI (async)
- SQLModel + Alembic
- Neon PostgreSQL (serverless)
- JWT verification (BETTER_AUTH_SECRET)
- OpenAI Agents SDK (agent + runner + tool calling)
- Cohere API (primary LLM – chat completions)
- Env:
  - DATABASE_URL (Neon)
  - BETTER_AUTH_SECRET
  - COHERE_API_KEY (for ai calls and primary LLM – keep private)
  - OPENAI_API_KEY (Agents SDK fallback / embeddings if needed)

### AI / Chatbot
- LLM: Cohere (primary) + OpenAI Agents SDK (tool orchestration)
- MCP: Official MCP SDK (5 tools: add_task, list_tasks, complete_task, delete_task, update_task)
- Chat endpoint: POST /api/{user_id}/chat (stateless)
- Conversation state: stored in Neon DB (Conversation + Message models)

### Authentication
- Better Auth (frontend signup/signin/session)
- Backend verifies JWT on all /api/* routes (except public auth if any)
- Token payload: {"sub": user_id (int), "exp": ...}

## 3. Phase 3 Chatbot Requirements (must be satisfied)

- Natural language interface for all 5 core Todo features
- Stateless server (conversation state in DB)
- AI uses MCP tools via OpenAI Agents SDK
- Primary LLM = Cohere (via Cohere API key)
- Fallback / tool orchestration via OpenAI Agents SDK
- Confirmations & graceful error handling in every response
- ChatKit UI (frontend) → calls /api/{user_id}/chat
- Full multi-user isolation
- Resumable conversations (after page refresh / server restart)

## 4. Quality, Security & Style Rules

- Async everywhere possible (routes, DB, LLM calls)
- Type hints & Pydantic validation
- Clean, readable code with English docstrings
- Follow PEP 8 (backend) & Prettier defaults (frontend)
- No magic strings/numbers — use constants
- Proper HTTP codes & error messages (401, 403, 404, 400)
- CORS: allow frontend origin only
- Logging: structured (no print)

## 5. Workflow & Phase Progression

1. Spec Writer creates/refines spec → approval
2. Architecture Planner updates architecture.md
3. Database Engineer implements models/migrations
4. MCP Engineer implements MCP tools
5. AI Agent Engineer implements agent & runner
6. Backend Engineer implements chat endpoint & integration
7. Frontend / ChatKit Engineer implements ChatKit UI
8. Integration Tester verifies full flow
9. Fix bugs → update spec first → re-implement

## 6. Phase 3 Success Criteria

- Chatbot understands natural language commands for all 5 core features
- Actions are confirmed in friendly language
- Conversation history persists across requests/restarts
- User isolation enforced (no cross-user data leak)
- ChatKit UI is responsive & AI-themed
- Works end-to-end: login → chat → task created/listed/updated/deleted/completed
- Uses Cohere for generation + OpenAI Agents SDK for tool orchestration

This constitution is **binding** for all agents and all phases (2 + 3).
Any deviation must be explicitly discussed and approved in writing.

All agents must reference this file in every interaction.
```
